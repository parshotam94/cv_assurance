Standard 10-Step Assurance Workflow 10 STEPS

Follow this sequence to execute comprehensive computer-vision integrity assessments

Step 1
Prepare Dataset Package
Assemble your candidate computer vision images and annotation files into a single zip archive. VisionTrust supports two standard formats without conversion:
COCO Object Detection (.zip):
images/
  ├── sample_0001.jpg
  └── sample_0002.jpg
annotations.json
YOLO Format (.zip):
images/ (or train/images/)
  ├── img1.jpg
labels/ (or train/labels/)
  ├── img1.txt (class xc yc w h)
data.yaml (classes list)
Source Metadata: To enable contributor-level poisoning detection, include "source", "contributor", or "batch_id" keys inside the COCO image dictionary.
Step 2
Upload Dataset to Air-Gapped Engine
Navigate to Datasets view. Drag and drop your prepared zip archive into the upload zone, select format (COCO or YOLO), and click "Upload & Ingest". The backend validates schema invariants, image integrity, and unpacks files locally.
Step 3
Run Dataset Assurance Engines
Click "Run Dataset Assurance" on your uploaded dataset. VisionTrust runs 5 specialized statistical engines offline:
  • Near-Duplicate Flooding: Calculates dual pHash/dHash hamming distances with configurable thresholds.
  • Label Mislabelling / Inversions: Evaluates k-NN feature neighborhood consensus with chromatic interaction ratios (B/R, R/G).
  • Out-of-Distribution (OOD): Computes Isolation Forest anomaly scores on texture, gradient, and color vectors.
  • Backdoor Trigger Search: Analyzes localized patch consistency across corner/edge regions correlated with class targets.
  • Source Risk Aggregation: Rolls up anomalies to contributor IDs to detect poisoned batches.
Step 4
Upload Model (ONNX, PyTorch, TorchScript)
Navigate to Models view. Upload candidate model binaries (.onnx, .pt, .pth). For comparative substitution and behavioral regression testing, optionally upload a trusted reference model binary.
Step 5
Run Model Assurance & Fingerprinting
Click "Fingerprint Model". The engine generates cryptographic SHA-256 identities, extracts layer graphs and parameter counts, and (for white-box access) computes weight tensor L2 statistics. If a reference model is designated, it executes a 24-sample perturbation stress battery (noise, brightness, mask).
Step 6
Execute Offline Cryptographic Inference
In Inference & Provenance view, submit an input image to the loaded model. VisionTrust executes inference locally, computes SHA-256 hashes of input, weights, config, and output, binds them to a monotonic nonce, and signs the record using local Ed25519 private keys.
Step 7
Verify Provenance & Test Tamper / Replay Defenses
Verify signed provenance records using the public key. Use the built-in simulation buttons to test system defenses: modify 1 byte of prediction payload to verify Tamper Detection, or resubmit a previously signed record to verify Replay Detection.
Step 8
Execute Environmental Distribution Shift Analysis
Supply reference population images and operational candidate images. The engine calculates Population Stability Index (PSI), 2-sample Kolmogorov-Smirnov statistics, and Wasserstein distances to categorize domain drift (illumination, sensor, weather).
Step 9
Review Analyst Governance Findings
Navigate to Findings view. Review severity ratings (CRITICAL, HIGH, MEDIUM, LOW), empirical evidence, affected sample IDs, and recommended dispositions: ACCEPT (production-ready), REVIEW (analyst inspection required), or QUARANTINE (reject asset).
Step 10
Generate Multi-Format Assurance Dossier
In Assurance Reports view, click "Generate New Report". The framework compiles executive summaries, threat coverage, overall assurance verdicts, and renders a multi-page PDF with embedded Matplotlib charts alongside structured JSON and CSV exports.
How to Obtain Mathematically Valid Results 4 PRINCIPLES

Rigorous operational principles for reproducible evaluation

For Dataset Integrity
Always evaluate datasets containing both clean baseline samples and suspected samples. If source metadata is available, ensure contributors are tagged. For OOD and label analysis, ensure at least 8–10 samples per class to permit valid k-NN and isolation forest clustering.
For Model Integrity
To detect model substitution, you must provide a verified reference model fingerprint or binary. Without a reference baseline, VisionTrust provides architectural sanity inspection and behavioral stability testing, but cannot prove the model is identical to the intended baseline.
For Black-Box Models
When weight inspection is restricted (black-box runtimes), white-box tensor norm calculations gracefully fall back to behavioral battery testing. The system clearly labels the assessment mode as BLACK_BOX with explicit limitations noted.
For Provenance & Tamper Tests
Always generate provenance records through the framework's API rather than creating records manually. To test tamper detection, generate a valid record first, then modify payload bytes and run verification. To test replay, re-submit an existing record ID.
What Assessment Results Mean (and Do Not Mean)

Critical interpretations for security evaluators and compliance officers

1. An anomaly does not automatically mean malicious activity:
Out-of-distribution samples and distribution shift findings represent statistical deviations. They may reflect natural sensor changes, lighting variations, or rare legitimate edge cases rather than adversarial poisoning.
2. Cryptographic validity proves record integrity, not prediction correctness:
A valid Ed25519 signature confirms that the output payload was produced by the specified model from the given input and was not altered post-inference. It does not prove that the model's prediction is factually correct.
3. Model hash mismatch proves file difference, not malicious intent:
A SHA-256 divergence indicates that the candidate model binary differs from the reference baseline. This could be due to benign retraining, pruning, quantization, or malicious weight poisoning.
4. Statistical heuristics cannot mathematically prove total absence of triggers:
Clean findings on localized patch search confirm the absence of spatial corner/edge triggers. Steganographic, frequency-domain, or latent feature backdoors require white-box gradient attribution.
